# AI 教具教学体系设计（从种子到体系）

> 目的：不再"见一个截图抄一个"，而是从教学的本质出发，定义一套可组合、可验证、可演进的体系：
> 最小可重用单元是什么，LLM 如何把它们组合成中等规模对象（板书段、交互图、测验），
> 再组合成节、讲、单元；学习过程中如何与学生交互；打断之后如何分岔与回归。
>
> 现状（已实现的"种子"）：手写单页画布、action 协议、教案（段 + 媒介决策）、探针图教具、SVG 示意图、课后习题、语义判分。
> 本文是下一阶段的蓝图；末尾有从现有代码迁移的分期计划。

---

## 0. 一句话结论

**把"教具"定义为一个有契约的可参数化组件目录（Gadget Catalog），让模型从目录里"选择并填参"，而不是每次写代码；
用"教学动作（Beat）"作为组合单位，用"课（Session）的认知弧线"约束顺序，用"分岔栈"处理打断。**
自由生成代码只保留为逃生舱，并且必须过渲染校验。

这条路线的理由来自这两天的实证：模型写自由代码的教具三次里有一次空白或跑题，而"从范例填参"的探针图一次成功；
教案里把媒介决策提前到规划层后，内容质量明显上升。体系化就是把这个经验推广到所有对象。

## 1. 教学的本质：一个好老师在小白板前做什么

从第一性原理出发，而不是从产品截图出发。一个优秀的一对一老师在白板前的行为可以完全分解为四类原子：

| 原子 | 老师的行为 | 性质 |
| --- | --- | --- |
| **Ink 墨迹** | 边说边写，写得很省（关键词、公式、箭头、表），圈、划、指 | 持久，留在板上，是这节课的外部记忆 |
| **Voice 语音** | 口语讲解，指着板书说，讲到关键处停一下 | 时间性、易逝，与墨迹严格同步 |
| **Act 行动** | 让学生先猜、动手拨一下模型、填一个空、指一下图 | 学生的输入，是学习真正发生的地方 |
| **React 反应** | 看到学生的动作后点评、提示、纠正误区、绕个弯再回来 | 老师的自适应，形成分岔 |

所有教学产品的"功能"都是这四类原子的组合。体系设计的任务是：
（1）把这四类原子定义清楚；（2）定义一层"预制、可测、有契约"的组合件；（3）定义组合规则和交互协议。

支撑的学习科学（只列会直接影响设计的）：
- Mayer 多媒体学习原则：**分段**（一次一个念头）、**信号**（圈画、高亮）、**时空邻近**（讲到什么写什么）、**形态**（语音 + 图，而非文字 + 图）、**冗余**（字幕不要照抄板书）。
- Predict–Observe–Explain：先让学生预测，再演示，再解释。这是"教具"存在的核心理由。
- 样例效应与渐隐（worked / faded examples）：先看完整解法，再把步骤逐步挖空。
- 检索练习与间隔重复：课后题不只是评估，是学习本身；跨节复习。
- 误区驱动（misconception-targeted）：每个错误选项对应一个真实误区，反馈针对误区而不是重复正确答案。
- 认知负荷：板书一次一个念头（通常 2~6 行，上限是软约束），画布上同时只有一个焦点。

## 2. 四层体系

```
Layer 3  课程结构       Unit ─ Lecture ─ Session（含标签、目标、误区、习题集、要点）
Layer 2  教学动作 Beat   Hook / Analogy / Predict-Observe-Explain / Define / Derive / WorkedExample /
                        Contrast / Counterexample / Apply / Recap / Remediate / Detour
Layer 1  教具 Gadget     有契约的可参数化组件（板书类 / 可视类 / 交互类 / 反馈类）
Layer 0  原子 Atom       Ink（text/math/table/figure/mark/frame/blank）· Voice（say/pause）·
                        Act（choose/type/drag/point/order/match/sketch）· React（verdict/hint/explain/reward/branch）
```

**LLM 在每一层做不同的事**：
- L3：结构规划（章、节、标签、目标、误区）——已实现。
- L2：为每一节选择教学动作序列（认知弧线），为每个动作选择教具——这是"教案"的升级版：段 → 动作，媒介 → 教具 id。
- L1：为选定的教具**填参数**（表达式、范围、标注、选项、误区、判分规则）——不写代码。
- L0：不直接接触，由编译器和渲染器处理。

只有两个逃生舱允许模型写代码：`Explorable`（自由 HTML 教具）和 `Diagram`（自由 SVG）。两者都必须过静态检查 + 无头渲染校验，并且规划层只在目录里没有合适教具时才允许选它们。

## 3. Layer 0：原子定义

### 3.1 Ink（画布上持久的东西）
| 原子 | 属性 | 说明 |
| --- | --- | --- |
| `text` | 内容、层级（0/1/2 缩进）、强调 | 一行手写字，不是段落 |
| `math` | LaTeX、行内/行间 | KaTeX |
| `table` | 表头、行、可高亮单元格 | 对比、分类 |
| `figure` | svg / image / reference、题注 | 静态图 |
| `mark` | 类型（circle/highlight/underline/arrow/strike）、目标（块 + 片段） | 信号，与语音同步 |
| `connector` | from → to、标签 | 块之间的箭头（推出、导致、对应） |
| `frame` | 标题、样式（紫色荧光标题） | 一列/一段的分栏标题 |
| `blank` | 期望答案、判分方式 | 板书上的空，可当场填（板书即题目） |

### 3.2 Voice（时间线）
| 原子 | 说明 |
| --- | --- |
| `say` | 一段口语，带真实音频时长；内部有 `at` 锚点供 mark / reveal 挂接 |
| `pause` | 等待：等学生回答、等学生操作满足条件、或固定时长 |

### 3.3 Act（学生输入）
`choose`（选一个）· `type`（填文本/数）· `drag`（滑块/顶点/拖拽排序）· `point`（在图上点某处）· `order`（排序）· `match`（配对）· `sketch`（画一条线）· `speak`（语音）。
每个 Act 产出一个**事件**，事件是导师"看见学生"的唯一途径（见第 7 节）。

### 3.4 React（导师反应）
`verdict`（对/错/部分对）· `hint`（阶梯提示）· `explain`（解析）· `reward`（掌握卡）· `branch`（进入分岔/回归）。

## 4. Layer 1：教具目录（Gadget Catalog）

### 4.1 什么是一个 Gadget
一个 Gadget 是**预制、参数化、有契约、经过测试**的组合件：

```
Gadget {
  id            : "FunctionPlot"
  purpose       : 一句话，规划层据此选择
  when / avoid  : 适用与不适用场景（能力卡）
  params_schema : JSON Schema（模型填这个）
  outputs       : 它能上报的学生事件 / 状态（供判分与反应）
  grading       : 可选，状态谓词或判分策略
  renderer      : 客户端确定性渲染（无需模型写代码）
  checks        : 参数校验 + 必要时无头渲染校验
  cost / risk   : 生成成本与失败风险等级
  example       : 一个填好的范例（few-shot）
}
```

规划层拿到的是"能力卡"（purpose/when/avoid/cost），生成层拿到的是该教具的 schema 和范例。这就是"让模型选择"的机制。

### 4.2 目录（按教学功能组织，不按视觉形式）

**A. 板书类（Ink 组合，全部确定性渲染）**

| id | 功能 | 关键参数 | 备注 |
| --- | --- | --- | --- |
| `NoteBlock` | 电报体要点 | 行（含层级、强调） | 现有 board |
| `Definition` | 术语三段式 | 术语、严格定义、白话、例子 | 每节最多 2 个 |
| `KeyFormula` | 公式各部分标注 | LaTeX、部件→含义、配色 | 圈画常落在这里 |
| `CompareTable` | 对比/分类 | 行（对象）× 列（属性）、可高亮单元格 | 表格高亮 |
| `DerivationSteps` | 逐行推导 | 步骤（式子 + 依据标签：代入/展开/由定义）、可挖空 | 逐行揭示，与语音同步 |
| `WorkedExample` | 样例 | 题目、步骤、答案；`faded` 指定哪些步骤挖空 | 样例→渐隐 |
| `Criteria` | 必须同时满足的条件 | 条件清单、反例 | 如"基的两个黄金法则" |
| `Timeline` | 顺序/演进 | 事件序列 | |
| `ConceptMap` | 概念关系 | 节点、边（mermaid） | |
| `CodeBlock` / `CodeTrace` | 代码与执行轨迹 | 代码、高亮行、变量表逐步 | CS 课必需 |

**B. 可视类（确定性渲染器；参数化优先，代码生成兜底）**

| id | 功能 | 关键参数 | 交互 |
| --- | --- | --- | --- |
| `FunctionPlot` | 函数随 x | 表达式、范围、包络/参考线、标注、参数滑块 | 探针读数 |
| `NumberLine` | 数轴/区间/极限 | 点、区间、箭头 | 探针 |
| `VectorDiagram2D` | 向量与线性组合 | 向量、系数滑块、张成区域、平行四边形 | 拖系数 |
| `GridLattice` | 网格/点阵/连接数 | n、连接规则、对比（2×2 vs 8×8） | 调 n |
| `GeometryScene` | 约束几何 | 点/线/圆与约束、可拖点 | GeoGebra-lite |
| `Scene3D` | 真三维 | 向量/平面/点、相机策略固定 | 旋转、滑块 |
| `Chart` | 数量对比 | 数据、图型 | 悬停 |
| `StateMachine` | 状态转移 | 状态、转移、当前态 | 单步 |
| `FlowDiagram` | 多方流程/资金流 | 参与方、有向边、动画令牌 | 播放 |
| `ReferenceFigure` | 教材原图 | figure_id、题注 | 无 |
| `Diagram` | 自由 SVG 示意图 | brief（元素、数量、标注） | 逃生舱（模型画） |
| `Explorable` | 自由 HTML 教具 | task | 逃生舱（模型写代码 + 渲染校验） |

原则：**能参数化的绝不生成代码**。`FunctionPlot`、`VectorDiagram2D`、`GridLattice` 三个就能覆盖这两天见到的所有探针图，且零失败。

**C. 交互类（Act + 判分）**

| id | 功能 | 输入 | 判分 |
| --- | --- | --- | --- |
| `Predict` | 先猜后看（POE） | 选项 | 不判对错，记录预测，随后 `reveal` 对照 |
| `Choice` | 单选 | 选项 + 每个错项的误区 | 精确 |
| `FillBlank` | 填空 | 文本 | 同义表 → 语义判分（LLM + rubric） |
| `Numeric` | 数值/带单位 | 数 | 容差、单位换算 |
| `Expression` | 代数式 | LaTeX | 符号等价（sympy） |
| `OrderSteps` | 排序 | 拖拽 | 序列匹配（允许等价段） |
| `MatchPairs` | 配对 | 拖拽 | 集合匹配 |
| `Estimate` | 估算 | 滑块 | 误差带，然后揭示真值 |
| `PointAt` | 在图上指 | 点击 | 热区 + 容差 |
| `ParameterHunt` | 把教具调到目标状态 | 拖动 | 状态谓词（教具上报状态） |
| `ErrorSpot` | 找错的一行 | 点击行 | 精确 |
| `SketchCompare` | 画一条曲线 | 笔迹 | 与真值曲线的几何相似度 |
| `OpenResponse` | 一句话解释 | 文本 | rubric 语义判分 |

**D. 反馈与巩固类**

| id | 功能 |
| --- | --- |
| `HintLadder` | 三级提示：方向 → 关键量 → 差一步 |
| `MisconceptionCard` | "你可能在想 X，其实 Y"，针对被选中的误区 |
| `Recap` | 要点回收（课堂要点列表的来源） |
| `MasteryBadge` | 掌握卡（现有 reward） |
| `ReviewQueue` | 跨节间隔复习：上一节答错的题在下一节开头出现 |

### 4.3 目录的演进规则
- 新增教具的门槛：有明确教学功能、参数可验证、有确定性渲染或有校验、附范例。
- 每个教具有使用统计（被选择率、失败率、学生答对率），低价值或高失败的教具下线或修范例。
- 目录本身是数据（`gadgets/*.yaml` + 渲染器），规划 prompt 从目录自动生成，不手写。

## 5. Layer 2：教学动作（Beat）

**Beat = 一段 `say` + 0..n 个板书教具 + 0..1 个可视教具 + 0..1 个交互教具 + 反应策略。**
它是"段"的升级：段只说讲什么和用什么媒介，动作还说明**教学意图的类型**，从而约束语气、板书形态和教具选择。

| 动作模板 | 意图 | 典型教具 | 语音约束 |
| --- | --- | --- | --- |
| `Hook` | 为什么该在乎 / 一个反直觉现象 | NoteBlock（一句钩子） | 结尾抛问题 |
| `Analogy` | 生活隐喻 | Diagram | 隐喻必须在后面被"回收"到严格定义 |
| `POE` | 预测→观察→解释 | Predict + FunctionPlot/VectorDiagram… | 先问后演 |
| `Define` | 严谨定义 | Definition / KeyFormula | 指着公式各部件说 |
| `Derive` | 逐步推导 | DerivationSteps | 每行一句"为什么可以这么做" |
| `WorkedExample` | 样例 | WorkedExample（faded） | 学生填被挖空的步骤 |
| `Contrast` | 对比/分类 | CompareTable | 高亮差异单元格 |
| `Counterexample` | 反例戳破误区 | Criteria + Diagram | "如果…会怎样" |
| `Apply` | 迁移到新情境 | Numeric / ParameterHunt | 让学生做 |
| `Recap` | 收束 | Recap + MasteryBadge | 不提问 |
| `Remediate` | 针对误区补救（条件插入） | MisconceptionCard + 一个小教具 | 由分岔触发 |
| `Detour` | 学生打断引出的岔路（1~3 个小动作） | 任意 | 结尾必须"回到主线" |

**一节课的认知弧线**（规划层的硬约束）：
`Hook → (Analogy | POE) → Define → (Derive | WorkedExample) → (Contrast | Counterexample) → Apply → Recap`，
5~8 个动作；至少 2 个带 Act 的门（gate）；至多 1 个可视教具为主教具，其余为静态图；最后一定 Recap。

## 6. 画布模型（无限画布 + 有界列）

规则来自"真实白板不擦"这一本质：画布是本节课的外部记忆，学生随时能回看。

1. **无限画布，列式流动。** 内容按列从左到右堆；每列是"一页"，高度上限 = 视口高度 − 底部字幕区。列内自上而下堆叠。
2. **不换行，只换列。** 列满了就开新列，绝不在列内压缩；宽度固定（约 560px），大教具独占一列。
3. **分栏标题。** 每个 `frame`（一个动作组或一个小节）在新列顶部用紫色荧光标题标出，正文缩进其下。
4. **焦点唯一。** 相机始终跟随当前在写的块（fit-visible）；语音与揭示同步；同一时刻只有一个块在"生长"。
5. **换页而非无限横向。** 一讲（Lecture）结束或主题切换时 `new_page`，页之间有导航；一页通常 3~6 列。
6. **鸟瞰。** 提供缩放 / 小地图，学生可回看任何一列；回看时不打断语音。
7. **岔路有位置。** 打断产生的 Detour 放在当前列右侧的"岔路列"，视觉上有边框和"岔路"标签，回归时相机回到主线。
8. **导出即笔记。** 画布可导出为图片/PDF，是学生带走的笔记。

关于"板书要不要换行"的回答：**不换行**。板书是电报体，一行一个念头；一块通常 2~6 行，推导和对比可以到 8~10 行，再多就拆块或开新列。
行数上限是**软约束**（lint 警告 + 引导拆块），不是硬错误，具体阈值要在实践中按学科调（数学推导和代码往往更长）。

**换列时的相机规则**：屏幕能同时放下 N 列（1440 宽约 2 列，大屏 3~4 列）。当第 N+1 列出现在屏幕右侧之外时，
视口平移到让**上一屏的最后一列成为新屏的第一列**，新列成为第二列，学生始终能看到刚讲完的那一列作为上下文；
不是整屏翻页，也不是只露出新列。回看时学生可以自由横向滚动，语音不中断。

## 7. 交互模型：过程中怎么跟学生互动

五种模式，运行时是一个状态机，模式之间由事件切换：

| 模式 | 谁主导 | 发生什么 | 退出条件 |
| --- | --- | --- | --- |
| **Narrate 讲述** | 导师 | 语音 + 板书生长 + 圈画 | 动作结束 / 学生打断 |
| **Gate 门** | 导师提问 | Predict / Choice / FillBlank…学生必须作答才能前进 | 作答 → React |
| **Explore 探索** | 学生 | 学生操作教具，教具上报事件（滑块值、点击、停留） | 学生说"好了" / 超时提示 / 满足目标 |
| **Exercise 练习** | 学生 | 课后题集，含提示阶梯与解析 | 完成 / 退出 |
| **Chat 侧栏** | 学生 | 元层对话："换个说法"、"跳过"、"慢一点"、"这个词什么意思" | 随时 |

设计原则：
- **对话是默认，提问是节拍。** 讲述里每 1~2 个动作就有一个门；门的问题是"你猜会怎样"而不是考试。
- **教具事件进入导师上下文。** 学生把 U 拉到 0.9，导师可以接一句"你把利用率拉满了，看利率"；这是"看见学生"。事件被节流并摘要（最近 N 个、停留时长、是否达到目标）。
- **门的作答有三种反应**：对 → 简短肯定 + 继续；错 → MisconceptionCard + 再来一次（不直接给答案）；再错 → 插入 `Remediate` 动作，然后才继续。
- **打断优先级高于一切**：立即暂停音频，记录当前动作与偏移，进入分岔（第 8 节）。
- **字幕直呼其名、语气随学习者模型调整**（见第 10 节）。

## 8. 分岔：打断之后怎么走

把一节课看成一张有向图，主线是一条路径，分岔是子图。运行时维护一个**动作栈**：

```
main: [Hook] [POE] [Define] [Derive] [Apply] [Recap]
                     ▲ 打断发生在 Derive 第 2 行
detour stack: [Detour: "为什么可以代入？"] → 回归到 Derive 第 2 行（从偏移处继续）
```

打断处理流程：
1. **意图分类**（LLM，带当前动作上下文）：
   - `clarify`：一句话能答（术语、上一句没听清）→ 行内回答，不分岔，继续。
   - `deepen`：需要展开（"为什么"、"能举个例子吗"）→ 生成 1~3 个 Detour 动作，放岔路列，讲完"回到主线"。
   - `challenge`：学生提出反对/反例 → 先肯定，再用 Counterexample 或 Criteria 回应，可能改写后续动作。
   - `navigate`：跳过 / 快一点 / 重讲 → 改变主线指针或语速，不生成内容。
   - `park`：跑题或超出本节 → 记入"停车场"，在 Recap 时回收或推荐下一节。
   - `misconception`：问题暴露了误区 → 立即插入 Remediate，并把该误区标记进学习者模型。
2. **状态保存**：打断时保存画布状态、当前动作 id、音频偏移；分岔结束后精确恢复。
3. **岔路有边界**：最多两层嵌套，单次岔路 ≤ 3 个动作；超出则改为"记下来，课后单开一节"。
4. **岔路进要点**：课堂要点列表里以缩进子项记录岔路，学生的问题本身成为这节课笔记的一部分。

答题驱动的分岔（无需学生打断）：
- 连续两次答错同一门 → Remediate；
- 快速答对且 Predict 正确 → 跳过标记为 `optional` 的展开动作（掌握式跳跃）；
- 课后题错题 → 进入 ReviewQueue，下一节开头以 `Review` 动作出现。

## 9. 题目体系

题目不是评估的附属，是学习本身（检索练习）。体系化的三个维度：

**认知层级**（每套题覆盖至少三层）：记忆（术语）→ 理解（换一种说法/判断对错）→ 应用（代入计算、迁移情境）→ 分析（找错、比较、解释为什么）。

**输入形态**（对应交互教具）：Choice · FillBlank · Numeric · Expression · OrderSteps · MatchPairs · PointAt · ParameterHunt · ErrorSpot · SketchCompare · OpenResponse。

**判分策略**（从确定到语义，能确定就不用模型）：
1. 精确/集合/序列匹配；2. 数值容差与单位；3. 符号等价（sympy）；4. 教具状态谓词（ParameterHunt）；5. 几何相似（Sketch）；6. 语义 rubric（LLM，给出理由）。
每道题声明自己的判分策略；语义判分必须返回"为什么对/错"，并把学生用词与标准术语的关系说清（已实现的填空判分就是这个）。

**反馈与循环**：提示阶梯（三级，按需）→ 判定 → 针对误区的解析 → 允许重试 → 错题进入 ReviewQueue → 下一节开头 Review → 掌握度更新。

**出题约束**（规划层）：每道题绑定一个动作或一个误区；互动题的教具必须沿用课上的同一模型；至少一道要动手算；选项等长互斥、错项对应真实误区；题干可含教具（PointAt、ParameterHunt）。

## 10. 学习者模型与因材施教（北极星：教会）

北极星指标不是"课生成得像不像"，而是**学生学完之后会不会**：每个概念的课后即时测通过率、延迟测通过率、达到掌握所需的时间。
预生成的教案是"给一般学生的中档讲法"，因材施教发生在**播放时**，靠三件事：知道学生在哪、有一架可以上下走的梯子、一个不放弃的补救回路。

### 10.1 学习者模型（已落地的部分 + 需要补的）

`learner[concept] = {memory, comprehension, structure, application}`（四维、只升不降，见 `src/content/mastery.py`）
+ `level ∈ {novice, standard, fast}`（本课入口分层，可被过程中的证据改写）
+ `pace`（语速与提问频度）+ `misconceptions[]` + `history[]`（append-only 事件，已有 `learner_events`）。
概念图（`concept_map.json`）提供先修边：**某概念学不会时，往回找的路径就是先修边**。

### 10.2 入口分层：先知道学生在哪

进入一节课前，用先修概念做 2~3 题诊断（来自概念图 prerequisite 边指向的概念，题从已有题库抽）；
已有掌握度证据的直接用证据，不再问。结果给出 `level`：
- `novice`：先修 < 40 → 讲解前先插入先修概念的 Remediate 小课，正课全速播放并多问一次；
- `standard`：按教案播放；
- `fast`：先修 > 75 且本概念 comprehension > 50 → 跳过 Hook/Analogy 类 beat，Derive/WorkedExample 压缩为"结论 + 一问"，答对即过，答错回落到 standard。
学生也可以自己说"我知道了/快一点/慢一点"，这是显式信号，优先级最高。

### 10.3 讲解梯子：同一个概念的三档讲法

每个 step 除了教案的中档版本，还有两档**按需生成、生成后缓存**的变体：
- `deeper`：换一个隐喻、加一个具体数字例子、把公式拆成两步（给 novice 和答错者）；
- `compressed`：只保留结论与一个检查问题（给 fast）。
变体沿用同一套 step 结构（板书 + 语音 + 装饰 + 教具控制），所以体验与正课完全一致（"答疑打断讲解对照系统看起来和正式教案没有区别"的原则不变）。
变体第一次生成时走岔路通道（≤ 20 秒首音），之后落盘到课程包 `variants/`，别的学生直接命中。

### 10.4 补救回路：反复讲到明白

触发：门答错两次 / 打断内容被分类为 misconception 或 "没听懂" / 课后题失败。
回路（每层都是一个 Detour 小课，结尾回到主线断点）：
1. **换法再讲**：同一概念的 `deeper` 变体 + 一个新的检查问题；
2. **回先修**：沿概念图先修边回退一层，讲先修概念的 `deeper` 版本，再回到本概念检查；
3. **换形式**：把讲解换成教具操作（让学生动手改参数）或费曼回合（让他讲给我听）；
4. 三层仍未通过 → 记入 `misconceptions[]`，把本概念放进复习队列，正课继续，不再当场死磕。
每一层都产生学习者证据（掌握度只在通过检查时上升）。

### 10.5 快学生不被拖慢

- beat 级跳过：教案每段标 beat（Hook/Analogy/POE/Define/Derive/WorkedExample/Contrast/Apply/Recap），fast 档默认跳过 Hook/Analogy，Recap 改为一道综合题；
- 每步右下角常驻"我懂了→"：跳过当前步剩余语音，直接进门；连续三次跳过且门全对 → 自动升到 fast；
- 提问频度随档位：novice 每步一问，standard 按教案，fast 只问 WorkedExample 与 Recap。

### 10.6 怎么知道教会了：模拟学生评测

在有真实用户之前，用 LLM 扮演三种学生（基础差 / 一般 / 很强，各带一段"已知/误区"设定）跟导师完整走一节课：
会答门、会在没听懂处打断、会说"快一点"。课后由独立的判卷模型出 5 道题测三种学生，得到每种学生的通过率与用时。
这就是北极星的离线版本：每次改教案 prompt、讲解梯子或补救回路，都跑一遍 20 节固定评测集看这三条曲线。
能机械判定的（门是否被跳过、补救是否回到主线、变体是否复用了正课板书对象）用代码判，不用模型。

## 11. LLM 的组合流程（生成即编译）

```
教材 ──ingest──▶ 文档模型（小节、页码、图）
        ──plan───▶ 课程树（Unit/Lecture/Session + 标签 + 目标 + 误区）           [L3]
        ──choreo─▶ 每节的动作序列：模板 + 教具 id + 意图 + 门                    [L2]  ← 目录能力卡
        ──fill───▶ 每个动作：语音、板书教具参数、可视教具参数、交互教具参数、反应   [L1]  ← 各教具 schema + 范例
        ──lint───▶ 结构校验 + 教学 lint + 渲染校验（逃生舱教具）
        ──compile▶ action 流（现有协议扩展一个通用 `gadget` 动作）
        ──run────▶ 运行时（动作栈、门、事件、分岔）
```

教学 lint（机器可检）：每个动作只引入 ≤ 1 个新概念；语音必须引用本动作的板书/教具（关键词交集）；每节 ≥ 2 个门；最后是 Recap；隐喻必须在 Define 里被回收；每个误区至少被一道题或一个 Counterexample 覆盖；板书 ≤ 6 行/块。

质量闭环：LLM-judge 按 rubric 给每节打分（清晰、指向性、门的质量、教具相关性）+ 人工抽查；prompt 与目录变更用同一套教材回归对比（已经在做的 `compare_*.png` 就是雏形）。

## 13. 与现有代码的对应与迁移计划

现有对象到体系的映射：`board`→NoteBlock，`illustration(svg)`→Diagram，`reference`→ReferenceFigure，`explorable`→Explorable（逃生舱），`ask`→Choice/Predict，习题三类→Choice/FillBlank/ParameterHunt，`reward`→MasteryBadge，段→动作（缺意图类型），教案→L3+L2 的一半。

分期（每期都端到端可跑、可对比）：

1. **目录与通用动作**：`src/gadgets/` 目录数据（yaml：能力卡 + schema + 范例）、协议加通用 `gadget` 动作、客户端渲染器注册表；把现有五种对象迁进目录。规划 prompt 从目录自动生成能力卡。
2. **三个参数化可视教具**：FunctionPlot、VectorDiagram2D、GridLattice（确定性渲染，替代大部分 Explorable）；CompareTable、DerivationSteps（逐行揭示 + 挖空）。
3. **动作层**：教案的段升级为动作模板 + 认知弧线校验 + 教学 lint；Predict（POE）与 HintLadder。
4. **交互与分岔**：教具事件上报（postMessage 契约）进导师上下文；打断意图分类与岔路列；Remediate 插入；动作栈状态保存/恢复。
5. **题目体系**：Numeric/Expression/OrderSteps/PointAt/ParameterHunt 判分策略；ReviewQueue 与下一节 Review 动作；学习者模型。
6. **质量闭环**：LLM-judge rubric、回归对比集、教具使用统计。

每期的验收都用同一份教材（CS251 讲义 + 线性代数讲义 + 夹逼定理）生成并截图对比。
